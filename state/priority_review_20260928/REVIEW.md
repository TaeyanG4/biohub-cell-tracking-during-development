# 2026-09-28 원점 재검토: 다음 실험의 우선순위

사용자 요청: HANDOFF를 처음부터 다시 읽고 현시점 가장 가능성 높은 방향을 찾는다.

**추천 1순위는 실제 C023 입력에서 일반 연결과 분열 사례를 함께 확보한 뒤, 배아를 완전히 나눠 frozen-detector Transformer를 추가 학습하는 것이다.** 이전 C037을 그대로 재실행하는 것이 아니라, 실제로 분열 정답이 0개였던 학습 데이터 구성을 수정하는 별도 실험이다. 현재 근거로 성공 확률이나 0.955 도달을 수치로 예측할 수는 없다.

이번 작업은 검토와 저장된 자료의 읽기 전용 진단을 완료했다. 새 학습, 추론, 그래프 변경, 제출, 알림 예약은 시작하지 않았다. C023/C024의 실제 0.954와 기존 최종 선택을 유지한다.

## 검토 범위와 판단 기준

- HANDOFF 전체 1–1386행, 현재 AGENTS, 실제 제출 원장, 기존 public-ideas audit와 두 차례 우선순위 검토, 초기 R3/C001/C002 자료를 읽었다.
- C032–C051의 종료 결과, C040의 배아 간 Transformer 검증, 9월 28일 source-overlap 정정과 전체 배아 분할 원칙을 함께 적용했다.
- 로컬 radar SQLite를 읽었다. 저장된 상위 공개 코드의 최고 점수는 0.953이며, 기존 x138 계열과 이미 검토한 Amanatar가 남아 있다. 마지막 실제 외부 갱신은 10:41 KST다. 이 검토를 최신 웹 전체 재검색으로 표현하지 않는다.
- 근거 순서는 실제 제출 점수, 새로운 학습 구성 요소의 배아 간 최종 그래프 결과, 실제 입력/감독 신호의 존재, 구현 및 검증 비용이다. 국소 최대 점수와 미실험이라는 사실만으로 순위를 높이지 않았다.

## 다시 읽으며 바로잡은 해석

1. **실제 성과가 반복 확인된 부분:** V1284 좌표 head 복원/선택, every-pair stabilization과 ILP-edge restore. 현재 C023/C024에는 이미 반영돼 있다.
2. **초기의 강한 성공 표현은 후속 정정을 따라야 한다:** C004의 0.948은 넓힌 분열 규칙이 아니라 validator가 선택한 strict 규칙의 결과다. GT 그래프에서의 분열 회수와 실제 예측 그래프의 회수는 다르다.
3. **국소 순위는 제출 순위가 아니다:** C029는 12-movie 국소 0.9646을 기록했지만 실제 0.950이었다. 기존 6bba→LB 회귀식은 후속 결과로 신뢰를 잃었다. 이를 새 실험의 기대 점수 계산에 쓰지 않는다.
4. **C008은 Transformer 추가 학습 전체의 실패가 아니다:** 정확한 production feature 계약 없이 별도 UNet 가중치를 섞은 0.926 사례다. C037은 실제 production 입력과 frozen UNet을 사용했고, C040은 같은 방식으로 실제 배아 간 최종 그래프 개선을 측정했다.
5. **분열 신호가 전혀 없다는 과거 주장은 오래된 movie 분할의 결과다:** C037은 원래 appearance 연구의 24개 movie를 가져왔고, 이 24개에는 분열 주석이 없다. 이후 whole-embryo 분할로 이 데이터 접근 제약이 해소됐다. C049/C050은 별도 CNN/특성 분류기를 재검증했으며, 분열 사례를 포함한 production-input Transformer 실험을 대신하지 않는다.
6. HANDOFF 20절의 과거 설명인 “candidate radius 때문에 Transformer가 먼 딸을 보지 못한다”는 21절의 실제 dense 검사로 정정됐다. Transformer는 모든 인접 프레임 쌍을 계산한다. 단순 반경 확대를 새 해결책으로 삼지 않는다.

## 이번에 새로 확인한 데이터

새 도구는 `audit_cached_evidence.py` 하나다. 기존 notebook의 matcher와 scorer를 호출하며 자체 경쟁 점수를 구현하지 않는다. C038이 저장한 C023 최종 그래프 97개의 원본 해시를 검증했고, visible4의 기존 edge/division 혼동행렬과 adjusted-edge 점수가 모두 정확히 재현됐다. 입력/소스 2,232개 해시는 실행 전후 동일하다. 상세 결과는 `evidence.json`, `division_coverage.csv`, `c002_peak_coverage.csv`에 있다.

### A. 분열 Transformer 감독 신호의 잠재적 범위

현재 C023 detector cache 좌표에 기존 공식 7 µm 일대일 매칭과 C037의 정수 좌표 규칙을 적용했다. C037의 학습 조건인 “정답 부모가 검출되고 같은 프레임에 알려진 부모 후보가 적어도 둘”도 검사했다.

| 배아 | 분열 주석 발생 수 | 부모 검출 | 두 딸 모두 검출 | 두 딸 모두 학습 정답으로 사용 가능성이 있는 경우 | 학습 가능한 딸 연결 수 |
|---|---:|---:|---:|---:|---:|
| 44b6 | 26 | 26 | 24 | 19 | 39 |
| 6bba | 125 | 125 | 121 | 121 | 246 |
| 합계 | 151 | 151 | 145 | 140 | 285 |

따라서 “분열 영상을 실제 검출기가 거의 놓쳐서 추가 학습할 정답이 없다”는 설명은 이 캐시에 맞지 않는다. C037 manifest의 분열 연결 정답은 실제로 양쪽 0개였다.

**이 수치는 실제 Transformer feature packet의 검증을 대신하지 않는다.** 또한 겹치는 crop이 있으므로 151건을 독립된 생물학적 사건 151개로 세면 안 된다. feature capture 전에 사건 중복/원본 범위를 점검하고, capture 후 실제 label 수와 minibatch 포함 수를 다시 확인해야 한다.

### B. 초기 C002의 별도 검출기는 보완 가능성이 있으나 바로 쓸 수 없다

이미 저장된 StrongUNet peaks를 공개 자료의 고정 평가 threshold 0.5로 읽었다. 임계값을 탐색하거나 그래프에 노드를 추가하지 않았다.

| visible movie | C023 미매칭 주석 노드 | StrongUNet에서 매칭되는 해당 노드 |
|---|---:|---:|
| 44b6_0113de3b | 3 | 3 |
| 44b6_0b24845f | 0 | 0 |
| 6bba_05b6850b | 4 | 3 |
| 6bba_05db0fb1 | 14 | 10 |
| 합계 | 21 | 16 |

독립 검출의 보완성은 남아 있다. 하지만 threshold 0.5에서 StrongUNet은 178,547 peaks를 만들며, C023 최종 노드는 121,300개다. C023 노드로부터 1.7 µm 넘게 떨어진 peaks도 107,430개다. 이는 새 진짜 세포 수나 FP 수가 아니며, 위치 차이와 중복도 포함한다. 16개를 올바른 추적으로 복구했다는 뜻도 아니다.

현재로서는 노드를 대량 추가할 근거가 없다. 진행한다면 양쪽 추적 문맥으로 제한된 위치에서 이 별도 검출기를 증거로 쓰는 진단이 먼저다. visible4만으로 일반화나 점수 이득을 주장할 수 없다.

## 1순위의 구체적인 다음 실험

검증 질문은 **“분열을 실제 포함하도록 감독 데이터를 수정하면, 알려진 일반 연결을 보존하면서 C023의 최종 추적 결과가 나아지는가?”**다.

1. 기존 `c037_transformer_study.py`/runtime의 capture·label·fit·predict와 기존 Queue/official replay를 재사용한다. 원본을 편집하지 않고 새 후보 폴더와 별도 등록된 작은 driver로 실행한다.
2. 전체 배아 분할을 적용한다. 44b6로 학습한 모델은 6bba에서, 6bba 모델은 44b6에서 평가한다. 기존 97-movie ID 제외 규칙으로 학습 데이터를 다시 비우지 않는다. unknown을 음성으로 바꾸지 않는다.
3. 분열 사례 및 일반 연결의 원본/중복/어려운 경쟁 후보 범위를 먼저 점검한다. 실제 production feature와 baseline logit 일치, 실제 분열 label 생성, 실제 학습 batch 포함을 확인한다. 정답 노드 위치만으로 가짜 production 입력을 만들지 않는다.
4. 고정된 단일 데이터 구성으로 두 fold를 학습한다. 기존 600-step recipe, frozen UNet/head/secondary model 및 regularization을 비교의 기준으로 두고 checkpoint/threshold sweep을 추가하지 않는다. 일반 연결을 유지하는 표집 규칙은 결과를 보기 전에 정한다.
5. 동일한 C023 대조군과 기존 C037 late600 결과에 대해 실제 22-movie 추론/공식 replay를 수행한다. 분열 개선뿐 아니라 일반 edge TP/FP/FN, 노드 수와 배아별 손상을 확인한다. 작은 효과도 일관된 그래프 근거가 있으면 검토한다.
6. 학습한 링크가 bidirectional fusion, ILP, Hungarian relink, restore 이후 어디까지 살아남는지 추적한다. 높은 daughter probability만으로 fork를 추가하지 않는다. 기존 ILP penalty 완화/무차별 fork 복원은 이미 음성이었다.
7. 유망하면 고정된 같은 방식으로 75개를 확장한다. 그 뒤에만 고정 deployment 모델·portable notebook·실제 T4 검증 및 제출을 판단한다. 배아 이름으로 배포 모델을 선택하지 않는다.

기존 C037 로그에서 24-movie capture는 약 25분, 600-step fit은 fold당 약 25–33초였고, 전체 18-job pilot는 약 1시간 55분이었다. 따라서 과거 감사 문서의 일괄 “16–24시간 학습” 추정은 현재 도구 비용을 설명하지 못한다. 새 데이터 capture와 검증이 주 비용이다. 정확한 ETA는 실제 movie/window 목록을 확정해 등록할 때 산정해야 하며, 현시점 예상 시간만으로 작업을 시작한 것으로 표현하지 않는다.

**실행 상태:** 이번 읽기 전용 감사는 완료. 기존 연구 queue/알림은 닫힌 상태이며 새 모델 실험은 아직 등록·시작하지 않았다.
